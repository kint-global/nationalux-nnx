Technical Architecture

From data integrity to verifiable NNX settlement

NNX is being developed as a hybrid data and settlement architecture. Current data/AI processing functions are separated from planned decentralized storage, privacy verification and on-chain settlement modules so that roadmap components are not presented as already deployed.

CURRENT · 01Data & MetadataEnterprise, public and digital datasets · metadata · integrity hashing
CURRENT · 02Semantic / AI-ReadySchema analysis · normalization · semantic mapping · quality processing
ROADMAP · 03Verifiable AccessIPFS / Arweave references · encrypted access · TEE / ZK verification where appropriate
ROADMAP · 04NNX SettlementEscrow modules · signed access events · transaction-hash audit references
ROADMAP

AI Agent Consumption API

REST/gRPC interfaces and EIP-712 signed workflows are planned for machine-to-machine access and eligible NNX-denominated settlement. Production deployment will be documented separately.

DESIGN PRINCIPLE

Off-chain Data · On-chain Proof

Raw enterprise data does not need to be publicly stored on Ethereum. Access credentials remain off-chain while hashes, signatures and settlement references can provide verifiable audit evidence.

Utility-led allocation for the NNX ecosystem

The NNX allocation framework defines purpose-based pools. Nationalux intends to strengthen treasury custody with verifiable on-chain lock or vesting controls as specific distributions are approved. Until such contracts are deployed, this website does not represent treasury balances as already time-locked.
